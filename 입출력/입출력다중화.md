# 높은 동시성의 비결: 입출력 다중화

> `파일`: N 바이트의 수열로, 모든 입출력 장치는 파일로 추상화된다.

파일은 컴퓨터에서 데이터를 저장하는 기본 단위인데, 운영체제는 이러한 파일들을 관리하고, 사용자와 프로그램이 파일에 접근하고 조작할 수 있도록 한다.

## 파일 서술자

파일 서술자는 운영체제가 열린 파일을 식별하기 위해 사용하는 추상화된 개념이다.

```markdown
1. 정의: 파일 서술자는 프로세스가 파일에 접근할 때 사용하는 고유한 식별자(보통 정수)입니다.
2. 기능: 운영체제는 파일 서술자를 통해 열린 파일의 정보(위치, 접근 모드 등)를 추적합니다.
3. 할당: 프로세스가 파일을 열면 운영체제는 파일 서술자를 할당합니다.
4. 사용: 프로그램은 파일 연산(읽기, 쓰기 등)을 수행할 때 이 파일 서술자를 사용합니다.
5. 표준 파일 서술자: UNIX 계열 시스템에서는 일반적으로 0(표준 입력), 1(표준 출력), 2(표준 에러)가 기본 파일 서술자로 사용됩니다.
```

프로세스마다 다음과 같이 생긴 파일 서술자 테이블이 있다.

```makefile
CopyFD  | File Table Entry
0   | stdin
1   | stdout
2   | stderr
3   | /home/user/file1.txt
4   | /home/user/file2.txt
5   | /dev/tty
```

### 서버에서 다중 입출력을 효율적으로 처리하는 방법

커널이 파일 서술자를 읽고 쓸 수 있는 시점을 대신 알려주도록 하여 어플리케이션이 수동적으로 동시성 처리가 가능해진다.

1. 파일 서술자를 획득한다.
2. 커널에게 파일 서술자를 전달한다.
3. 읽고 쓸 수 있는 상태가 되었을 때 파일 서술자가 반환되어 상응하는 처리를 수행한다.

위와 같이 구현하는 방식을 `입출력 다중화(I/O Multiplexing)`라고 한다.

다중화는 여러 신호를 하나로 합치는 것을 말한다. 입출력 다중화는 select, poll, epoll 함수로 구현이 가능하고 이를 통해 파일 서술자들을 효과적으로 감시하고 처리할 수 있게 된다.

1. select: 1024개의 파일 서술자 묶음이라는 개수 제한이 존재
2. poll: 개수 제한 문제 해결
3. epoll: 준비 완료된 파일 서술자 목록을 생성하여 효율성 증가
