## 1.프로그래밍 언어부터 프로그램 실행까지, 이렇게 진행된다.

### 프로그래밍 언어

프로그래밍 언어는 저수준에서 고수준 언어로 발전해나갔다. (천공카드 -> 어셈블리어 -> 고급 프로그래밍 언어 -> 해석형 언어)

### 컴파일러

고수준 언어를 저수준 언어로 번역하는 프로그램으로, 어휘 분석 -> 구문 분석 -> 의미 분석 -> 중간 코드 생성 -> 코드 생성의 단계를 거친다.

### 링커

여러 개의 대상 파일을 합쳐 하나의 실행 파일을 만드는 프로그램으로, 심벌 해석, 실행 파일 생성, 재배치를 담당한다.
실행 파일 생선 단계에서 실행파일 각각이 lib을 내부에 가지고 있다면 `정적 라이브러리`, lib과 실행파일이 별도로 존재하여 lib을 공유하면서 사용하는 것이 `동적 라이브러리`이다.

## 2. 프로그램이 실행되었지만, 뭐가 뭔지 하나도 모르겠다.

### CPU의 기본 동작

CPU가 하는 일은 메모리에서 명령어를 가져오고 실행하는 행위를 반복하는 것뿐입니다. CPU는 운영체제, 프로세스, 스레드와 같은 개념을 알지 못합니다.

### 멀티태스킹의 구현

CPU에게 여러 프로그램들을 실행시키기 위해서는 `로더`같은 것들을 통해 프로그램을 일시 중지했다가 다시 시작할 수 있게 해야 합니다. 이때, 프로그램의 상태 정보를 구조체를 통해 기록했고 이를 `프로세스`라고 부릅니다.

### 프로세스와 스레드

복잡한 프로그램은 여러 개의 프로세스가 협업을 해야 하는데, 프로세스간의 통신은 부담이 컸습니다. 이를 해결하기 위해 프로세스 위에서 여러 실행 흐름을 만들게 됐고, 이를 `스레드`라고 부릅니다.

### 비동기 프로그래밍의 필요성

멀티 태스킹을 할 수 있지만, `동기적`으로 작동한다면 효과적이지 않기 때문에 `비동기`로 프로그래밍을 해야 합니다.

### 비동기 프로그래밍 방법

비동기로 프로그래밍하는 방법은 `코루틴`과 `콜백 함수`를 통해 구현할 수 있습니다.

코루틴: 함수의 동작에 일시 중지와 재개 기능이 있는 것입니다.
콜백 함수: 함수를 인자로 전달하여 특정 이벤트 발생 시 실행되도록 하는 방식입니다.

## 3. 메모리의 본질, 포인터와 참조

### 포인터와 참조

변수에 값과 메모리 주소를 모두 저장하기 위해 `포인터`가 등장하였고, 하드웨어를 직접적으로 조작할 수 있기 때문에 포인터를 한 번 더 추상화한 `참조`가 등장하였다.

(참조는 주소에 직접적인 접근이나 조작이 불가능하다.)

### 프로세스 주소 공간

프로세스 주소 공간은 `커널 +스택 + 힙 + 데이터+ 코드`영역으로 이루어져 있다.

### 스택 영역

함수의 호출 관리는 스택 영역에서 담당하며, `스택 프레임`에 함수 호출에 필요한 데이터(지역 변수, 매개변수, 반환 주소 등)를 저장한다.

### 힙 영역

동적 메모리의 할당과 해제를 위해 사용된다. 메모리 할당 전략에는 최초 적합 방식, 다음 적합 방식, 최적 적합 방식이 있다.

전체적인 메모리 할당 과정은 다음과 같다.

```markdown
1. malloc 호출
      1. 적당한 여유 조각 발견 → 할당
      2. 적당한 여유 조각 발견 X → 힙 영역 확장하기 위해 시스템 콜
            1. brk가 호출되어 커널 상태로 전환
            2. 운영 체제의 가상 메모리 시스템이 힙 영역 확장
            3. brk 실행 종료 → 사용자 상태로 전환 및 malloc이 여유 메모리 조각 반환
2. 메모리 사용 중
      1. 새로 요청된 메모리 읽거나 쓰기 시도 → 페이지 인터셉트 발생
      2. 커널 상태로 전환 → 운영체제가 실제 메모리 할당 → 사상 관계 설정
      3. 사용자 상태로 변경
```

### 메모리 풀

일부 상황을 위한 메모리 할당을 위해 한 번에 큰 메모리 조각을 요청하고 내부에서 자체적으로 메모리를 할당/해제를 관리하는 것을 `메모리 풀`이라고 한다.

### SSD

SSD는

1. CPU와 다른 주소 단위를 사용한다.
2. 가상 메모리의 주소 지정 범위보다 훨씬 큰 용량을 가진다.
3. 잦은 읽기/쓰기 작업에는 수명이 짧아질 수 있다.

위와 같은 특징 때문에 메모리로 적합하지 않다.

## 4. 트랜지스터에서 CPU로, 이보다 더 중요한 것은 없다

### 1. 기본 구조

- CPU는 트랜지스터로 구성되어 전류의 흐름을 제어해 연산을 처리
- 논리 게이트(AND, OR, NOT)를 조합하여 복잡한 연산 수행
- ALU(산술 논리 장치)가 실제 연산을 담당
- 레지스터는 CPU 내부의 고속 메모리로 데이터와 명령어 처리에 사용
- 클럭 신호로 모든 동작을 동기화

### 2. 유휴 상태 관리

- System Idle Process가 CPU의 유휴 상태를 관리
- 'halt' 명령어로 저전력 상태 진입
- 주기적인 타이머 인터럽트로 다른 작업 확인

### 3. 데이터 처리

- 2진법 체계 사용 (n비트로 2^n개의 값 표현)
- 부호 있는 정수는 2의 보수 방식으로 표현

### 4. 분기 예측

- 조건문 실행 시 파이프라인 효율을 위해 분기 예측 수행
- 예측 실패 시 파이프라인 무효화로 성능 저하
- 정적/동적 예측 방법 사용

### 5. CPU 아키텍처 진화

- CISC: 복잡한 명령어 세트, 다양한 기능 제공
- RISC: 간단한 명령어 세트, 파이프라인 효율 높음
- 현대 CPU: CISC와 RISC의 장점을 결합, 마이크로 명령어와 하이퍼스레딩 기술 활용

## 5. 작은 것으로 큰 성과 이루기, 캐시

### 캐시

CPU가 메모리에 접근하여 데이터를 가져올 경우가 많은데, 둘의 속도 차이가 많이 나기 때문에 최근에 얻었던 데이터를 캐시에 저장하게 되었다.

- 캐시와 메모리 사이 데이터 일관성은 연속 기입이나 후기입 방법을 통해 유지한다.
- 다중 코어에서 캐시의 일관성은 캐시를 업데이트할 때 다른 코어의 캐시도 함께 업데이트하여 해결한다.
- 컴퓨터 저장 체계의 각 계층이 다음 계층에 대한 캐시 역할을 하고, 이 때 캐시 용량과 속도는 반비례한다. (디스크의 캐시로 메모리를, 파일 시스템의 캐시로 디스크나 메모리를 사용한다.)

### 캐시 친화적인 프로그램

시간적 지역성과 공간적 지역성을 고려하여 캐시 친화적인 프로그램을 작성할 수 있다.

### 다중 스레드 성능 방해자

캐시 튕김 문제나 거짓 공유 문제로 인해 다중 스레드임에도 단일 스레드보다 낮은 성능을 보일 수 있다.

### 다중 스레드의 비순차적 실행 현상

- 컴파일 단계나 실행 단계에서 비순차적 실행이 일어날 수 있다.
- 버퍼에만 데이터의 변경이 반영된 상태에서 다른 스레드의 접근/변경이 일어나면 비순차적 실행을 겪을 수 있다. -> 잠금을 통한 보호나 CAS 알고리즘을 통해 해결한다.

### 메모리 장벽

명령어의 비순차적 실행을 해결하기 위해 등장한 개념으로 특정 코어를 다른 코어가 보았을 때 언행이 일치하도록 만든다.

### 잠금 프로그래밍

잠금을 이용한 프로그래밍은 공유 리소스를 보호하기 위해서 스레드 하나만 상호 배제를 보유하여 잠금을 사용한다.

- `상호 배제`: 다른 스레드는 대기 상태로 진입하여 잠금이 해제될 때까지 기다린다.
- `스핀 잠금`: 잠금을 요청하는 스레드가 대기 상태에 진입하지 않고, 반복적으로 잠금이 해제되었는지 확인한다. (순환 대기)

잠금 없는 프로그래밍은 스레드가 대기 없이 어떤 일을 하는 것에 가치를 두고 있다.

## 6. 입출력이 없는 컴퓨터가 있을까?

### CPU와 입출력 처리

외부 장치는 장치 레지스터를 통해 데이터와 제어/상태 정보를 저장합니다.
입출력 명령어(x86에서는 IN과 OUT)를 사용해 장치 레지스터를 읽고 씁니다.
인터럽트를 통해 비동기적으로 입출력 상태 변화를 감지합니다.

### 장치 제어기와 DMA

현대 장치 제어기는 자체 프로세서와 펌웨어를 갖추고 있어 CPU 개입 없이 복잡한 작업 수행이 가능합니다.
DMA(Direct Memory Access)를 통해 CPU 개입 없이 장치와 메모리 간 직접 데이터 전송이 가능합니다.

### 파일 읽기 프로세스

시스템 호출을 통해 커널에서 디스크 명령어로 변환됩니다.
디스크 입출력 동안 프로세스는 블로킹 대기열에 배치되고, CPU는 다른 프로세스를 실행합니다.

### 입출력 다중화

select, poll, epoll 함수를 사용해 여러 파일 서술자를 효율적으로 관리합니다.
커널에 변화 감지를 위임하여 인터럽트로 처리함으로써 효율성을 높입니다.

### mmap을 통한 파일 처리

파일을 프로세스의 주소 공간에 직접 매핑하여 메모리처럼 접근 가능하게 합니다.
큰 파일 처리와 동적 링크 라이브러리 로딩에 효과적입니다.

### 입출력 지연

디스크 접근은 캐시나 메모리 접근에 비해 현저히 느립니다(ms 단위).
캐시 계층 구조를 통해 성능 차이를 완화합니다.
