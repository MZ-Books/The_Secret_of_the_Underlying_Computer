# 멀티 스레드의 성능 방해자

멀티 스레드가 단일 스레드보다 성능이 안 좋은 상황이 발생할 수 있다.

```markdown
💡 캐시 튕김 문제

: 캐시 핑퐁이라고도 불린다. 각자의 스레드에서 각자의 캐시에 동일한 데이터를 저장하고 있다면, 한 스레드 캐시에서 해당 데이터를 수정하려면 다른 스레드 캐시에 저장된 데이터를 무효화해야 한다.

이러한 현상이 쌓이면 멀티 스레드임에도 단일 스레드보다 낮은 성능을 보일 수 있다.

→ 멀티 스레드에서는 최대한 데이터 공유를 피하는 것이 좋다.
```

```markdown
💡 거짓 공유 문제
: 동일한 데이터를 저장 및 변경하지 않더라도, 캐시에 데이터를 저장할 때 해당 데이터가 아닌 캐시 라인을 저장하기 때문에 데이터 공유를 피해도 멀티 스레드가 단일 스레드보다 속도가 느릴 수 있다.

→ 멀티 스레드에서 동일한 캐시 라인을 저장하지 않도록 변수의 순서를 조정하여 해결할 수 있다.
```

`캐시 라인` : 공간적 지역성을 위해서 캐시에 데이터를 저장할 때 함께 저장하는 해당 데이터가 있는 곳의 ‘묶음’ 데이터

# 비순차적 실행

멀티 스레드 환경에서는 소스 코드가 순차적으로 실행되지 않는 것처럼 보이는 현상이 있다.

단일 스레드 내에서는 순차적 실행과 동일한 결과를 보장하지만, 멀티 스레드 환경에서는 비순차적 실행 현상들이 나타날 수 있다.

## 1. 캐시

캐시를 갱신하고 캐시의 일관성을 유지시키는 작업은 오래 걸리기 때문에, CPU와 캐시 사이에 저장 버퍼라는 단계를 추가하여 기록 작업이 이뤄지는 동안 CPU가 나머지 작업을 수행하도록 할 수 있다.

→ 멀티 스레드 환경에서 한 데이터의 변경이 저장 버퍼에만 반영된 상태에서 다른 스레드에서 해당 데이터를 접근 및 변경하면 실행 순서가 변경된 듯한 현상을 겪을 수도 있다.

⇒ `잠금`을 통한 보호를 사용하거나 `CAS 알고리즘`(실행되거나 되지 않는 두 가지 상태만 가지고 원자성 작업 실행)을 통해 해결한다.

## 2. 명령어의 비순차적 실행: 컴파일러와 OoOE

프로그래머가 작성한 코드는

1. 컴파일 단계
2. 실행 단계

에서 순서가 변경될 수 있다.

```markdown
💡 실행 단계에서 순서가 바뀌는 이유?

CPU가 기계 명령어를 순서대로 실행하면 피연산자가 아직 준비되지 않은 경우가 생길 수 있어 파이프라인에 빈 공간(슬롯)이 발생한다.
→ 이미 준비 완료된 다른 명령어를 먼저 실행하여 실행 속도를 높인다.
```

# 메모리 장벽

명령어의 비순차적 실행을 해결하기 위해 `메모리 장벽` 등장

: 특정 코어를 다른 코어가 보았을 때 언행이 일치하도록 만든다.

## LoadLoad

: CPU가 Load 명령어일 때, 다음에 오는 Load 명령어가 부정출발로 먼저 실행되는 것을 방지한다.

## StoreStore

: CPU가 Store 명령어를 실행할 때, 다음에 오는 Store 명령어가 먼저 실행되는 것을 방지한다.

## LoadStore

: CPU가 Load 명령어를 실행할 때, 다음에 오는 Store 명령어가 먼저 실행되는 것을 방지한다.

- Load 명령어가 캐시에 적중하지 못했을 때 발생할 수 있다.

## StoreLoad

: CPU가 Store 명령어를 실행할 때, 다음에 오는 Load 명령어가 먼저 실행되는 것을 방지한다.

- StoreLoad 장벽이 실행된 후 다른 코어가 메모리 장벽 이전의 변수를 읽으면 곧바로 최신 값이라는 것을 보장한다.

# 메모리 모델

메모리 모델은 프로그래밍 언어와 컴퓨터 시스템에서 메모리 일관성(메모리 모델)을 정의하는 규칙과 행동을 의미합니다. 메모리 모델은 멀티 스레드 프로그램에서 메모리 접근의 순서를 결정하는 데 중요한 역할을 합니다.

- 강한 메모리 모델이 약한 메모리 모델보다 더 엄격하게 스레드 간 메모리 일관성을 유지한다.

# 잠금 프로그래밍과 잠금 없는 프로그래밍

잠금을 이용한 프로그래밍은 공유 리소스를 보호하기 위해서 스레드 하나만 상호 배제를 보유하여 잠금을 사용한다.

## 상호 배제(Mutual Exclusion)

상호 배제는 여러 스레드가 동시에 특정 자원에 접근하지 못하도록 하는 메커니즘입니다. 이를 통해 공유 자원의 일관성을 유지하고 충돌을 방지합니다. 상호 배제를 구현하는 주요 도구 중 하나가 뮤텍스(mutex)입니다.

## 스핀 잠금(Spin Lock)

스핀 잠금은 상호 배제를 구현하는 방법 중 하나로, 잠금을 획득하려는 스레드가 잠금이 해제될 때까지 반복적으로 잠금 상태를 확인하면서 바쁘게 대기(busy-waiting)하는 방식입니다.

이와 달리, 잠금 없는 프로그래밍은 스레드가 대기 없이 어떤 일을 하는 것에 가치를 두고 있다.
